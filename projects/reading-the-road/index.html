A classical vision pipeline

This project detects road lanes using C++14 and OpenCV. It works directly with image colors, edges, and line geometry: each video frame passes through a sequence of filters before the estimated left and right lane boundaries are drawn back onto the image.

The demonstration below comes from the repository’s lane_detection.gif, converted to video for playback.

The processing sequence

The LaneDetection function makes the pipeline explicit. Color filtering retains likely lane markings; a region-of-interest mask focuses on the road; Canny extracts edges; the Hough transform finds line segments; and a weighted blend combines the resulting overlay with the original frame.

Finding yellow and white markings

The color filter converts the image to HLS and constructs separate masks for yellow and white. The yellow mask uses lower and upper bounds of (10, 0, 90) and (50, 255, 255). The white mask selects high lightness with a lower bound of 190. Combining the masks retains candidate markings before the geometric stages.

Focusing on the road

The region of interest is a trapezoid. Its lower edge spans the image width, while its upper edge runs from 45% to 55% of the image width at 60% of the image height. The implementation fills this polygon into a mask and applies it with bitwise_and, removing image regions outside the expected road area.

From edges to line segments

Canny runs on the grayscale masked image with thresholds of 50 and 120. The probabilistic Hough transform then uses a one-pixel distance resolution, a one-degree angular resolution, a vote threshold of 10, a minimum line length of 20 pixels, and a maximum gap of 100 pixels.

Estimating the lane boundaries

The drawing stage separates candidate segments by slope and position. Right-lane candidates require a slope above 0.3 and an initial x-coordinate above 500 pixels. Left-lane candidates require a slope below −0.3 and an initial x-coordinate below 600 pixels.

For each side, the code averages slopes and intercepts, then extrapolates a boundary from 65% of the image height to the bottom. It fills the polygon between the boundaries and draws the two lane lines. The excerpt shows the averages and left-boundary calculation; the right boundary uses the same approach.

The overlay is combined with the source image using addWeighted, with default weights of 0.8 for the overlay and 1.0 for the original frame.

Building and running the project

The CMake configuration requires CMake 3.17.2 or newer, selects C++14, and links the LaneDetection executable against OpenCV. Run the program on a machine with OpenCV installed and a graphical display. It prompts for a video path, processes frames until the stream ends, and also exits when Escape is pressed.

Scope and next steps

The implementation is a compact, frame-by-frame lane detector. Its color thresholds, slope filters, and fixed horizontal cutoffs encode assumptions about the scene. The boundary model is straight-line based, and the code does not carry lane estimates forward between frames.

Useful next steps would be handling frames with no valid candidates before computing averages, replacing pixel-specific cutoffs with normalized coordinates, and adding temporal smoothing. These are possible extensions to the current code.
